## Failed Build Diagnostics

**Symptoms:** CI check `Require valid script-generated diagnostic bundle` fails.
Diagnostic `.logd` file is reported as invalid or too small.

**Root cause:** The diagnostic bundle was manually created, copied, or edited instead
of being generated by `python3 build.py`. Only the `encryptly` tool can produce a
valid encrypted archive.

**Resolution:**

```bash
# 1. Rebase onto the current upstream branch
git fetch upstream
git rebase upstream/main

# 2. Run the build script to generate fresh diagnostics
python3 build.py

# 3. Push the commit (build.py auto-commits diagnostic artifacts)
git push --force-with-lease
```

**Validation:** The CI check `Require valid script-generated diagnostic bundle` should
pass with `conclusion: success`.

**Important:** Do **not** manually create, copy, or edit diagnostic files. The
`build-00000000` files in the repository are stubs and are **not** valid payout
evidence.

## Unhealthy Service Check

**Symptoms:** Health check endpoint returns non-200 status, or the Prometheus alert
`ServiceDown` fires.

**Resolution:**

```bash
# 1. Run the health check tool to verify service status
python3 tools/health_check.py --service backend --endpoint /health

# 2. For Prometheus-compatible output
python3 tools/health_check.py --service backend --format prometheus

# 3. Check recent deployment history to identify potential causes
python3 tools/deploy.py history --service backend

# 4. If a bad deployment is identified, initiate rollback
python3 tools/deploy.py rollback --service backend --version <previous-version>
```

**Validation:** Health check returns `{"status": "ok"}` and `ServiceDown` alert
clears within 5 minutes.

## Bad Deployment

**Symptoms:** Service errors spike after a deployment, latency increases, or users
report issues. Identified via Grafana dashboard (`tot-api-performance`) or
deployment history.

**Resolution:**

```bash
# 1. Check deployment history for the affected service
python3 tools/deploy.py history --service backend --environment production

# 2. Inspect the health of the current deployment
python3 tools/health_check.py --service backend --endpoint /health

# 3. Initiate a dry-run rollback to preview changes
python3 tools/deploy.py rollback --dry-run --service backend

# 4. Perform the rollback
python3 tools/deploy.py rollback --service backend

# 5. Export the incident timeline for post-mortem
python3 tools/deploy.py history --service backend --format json
```

**Validation:** Service health checks pass, error rates return to baseline, and
deployment history shows the rollback.

## Migration Failure

**Symptoms:** Database migration fails with errors, or the `db_migration.py` script
exits non-zero. Services may be degraded or unavailable.

**Resolution:**

```bash
# 1. Check migration status
python3 tools/db_migration.py status

# 2. Review the migration log for specific errors
python3 tools/db_migration.py status --json

# 3. If migrations are applied but inconsistent, manually verify:
#    - Check database connection
#    - Verify migration files exist on disk
#    - Confirm migration checksums match

# 4. For failed migrations, verify the database state is consistent
python3 tools/health_check.py --service backend --endpoint /health
```

**Validation:** `db_migration.py status` exits zero with no pending or inconsistent
migrations. All health checks pass.

## OpenAPI Contract Regression

**Symptoms:** API consumers report unexpected changes in response format, or the
OpenAPI diff tool reports breaking changes between deployments.

**Resolution:**

```bash
# 1. Run the OpenAPI diff tool to see what changed
python3 tools/openapi_diff.py docs/openapi/v3.yaml

# 2. Validate enum values in the schema
#    (requires Haskell tooling from tools/)
# haskell tools/openapi_enum_validator.hs docs/openapi/v3.yaml

# 3. If breaking changes are unintentional, revert the change and re-deploy
python3 tools/deploy.py rollback --service backend

# 4. Export the deployment history for audit
python3 tools/deploy.py history --format json
```

**Validation:** OpenAPI diff shows no unexpected breaking changes. Consumers
confirm the API contract is consistent.
